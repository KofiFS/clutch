# Security review and fixes (2026-11-18)

Two reviews: the desktop app (by hand) and the cloud server (separate reviewer). Every fix below has a test: `npm run test:e2e` (app) and `cd server && npm test` (server).

## Desktop app

| Issue | Risk | Fix |
|---|---|---|
| `system:openExternal` opened any URL the UI sent (`file:`, `ms-settings:`, `search-ms:`…) | A bug or injected script in the UI could launch programs | Only `https:`, `http:` and `mailto:` open (`src/main/security.ts`); server-sent links (checkout, sign-in, YouTube) go through the same check |
| `library:update` accepted any field, including `file` and `thumbnail` | The UI could point a clip at any file, then delete it from the trash | Only `title`, `tags`, `favorite`, `game` are accepted from the UI; deletes are limited to video files |
| `cf://` served any file type inside the data folder | `settings.json` (webhook, API key) was readable as a "media" URL | `cf://` serves only video and image files; the app folder check uses a real path-inside test |
| Main and corner windows ran unsandboxed | A renderer bug had more reach | `sandbox: true` on both windows; navigation and new windows are locked; webviews refused; permissions limited to screen, mic and clipboard write |
| Discord webhook, Anthropic key, YouTube client secret and YouTube tokens stored as plain text | Any program or backup could read them | Encrypted with Windows DPAPI (`secrets.bin`, encrypted token file); settings.json keeps blanks. Older versions just see them as not set |
| YouTube "own app" sign-in had no `state`, and the error page reflected text unescaped | Login CSRF and HTML injection on the loopback page | Random `state` checked; output escaped |
| Sign-in loopback accepted any token | A sign-in link started by someone else could log you into their account | Random nonce in the loopback URL, checked on return |
| `deepMerge` copied `__proto__` keys | Prototype tampering from a crafted settings file | Those keys are skipped |
| No Electron fuses | `ELECTRON_RUN_AS_NODE` / `--inspect` could turn Clutch.exe into a Node runtime | Fuses: no run-as-node, no NODE_OPTIONS, no inspect flags, asar integrity, load only from asar |
| Test and demo copies could rewrite the Windows startup entry | A test run could break the installed app's auto-start | Copies with `CLUTCH_USER_DATA` never touch it |

## Cloud server (not deployed yet)

| Issue | Fix |
|---|---|
| Parallel requests could skip the daily AI limits (counted after the body was read, in memory) | A slot is taken atomically in SQLite before any work, handed back on bad input; server-wide daily cap `AI_DAILY_CAP` (default 3000) |
| S3 uploads didn't enforce size, so the storage quota could be bypassed | Content-Length and Content-Type are signed into the upload link; `/complete` checks the real size against the claim and the quota, and deletes on mismatch |
| Thumbnails and leftover upload links escaped the quota | Thumbnails count; minimum clip size; upload links work only while the clip is pending; deleted clips' files are swept again |
| Anyone could link their YouTube channel to an attacker's Clutch account | The browser returns to the app's loopback; the app finishes with its own session; the server requires the same user |
| `DEV_LOGIN=1` worked on a public server, and the example JWT secret was kept | Refuses to start unless `PUBLIC_URL` is loopback; example secret never used |
| S3 media could be served as HTML | Downloads force `video/mp4` / `image/jpeg` and a content disposition; local media sends `nosniff` and a sandbox CSP |
| Fake ad clicks for made-up ids | Only ids in `ads.json` count |
| Expired share links worked until the hourly cleanup | Expiry checked on every request |

Not changed (worth doing before launch): per-IP rate limits, session revocation (`token_version`), and moving the session token out of the sign-in redirect URL.

## Strix pentest (2026-11-19)

Strix 1.7.0 ran a deep white-box scan of the app and the server (Claude Sonnet 5.5, $10.84). It found 13 issues; the full report and each proof of concept are in `strix-2026-11-19/`. All fixes have tests.

| Strix id | Severity | Issue | Fix |
|---|---|---|---|
| vuln-0006 | High | An app-audio program name went into a PowerShell command; a renderer bug could store `$(...)` and run commands | Program names must be plain file-name characters (`isSafeProcessName`), checked both when saved and before PowerShell |
| vuln-0013 | Medium | `settings:set` could point a library or the clips folder at a program, which "Open folder" would then launch | `settings:set` now goes through `settingsPatchFromRenderer`: libraries and the cloud copy can't be changed through it, the clips folder must be an existing folder; both open handlers only open folders |
| vuln-0011 | Medium | Changing the server address sent the session token to the new server | The token is stored with the server it came from and is only sent there; changing servers signs out. Server addresses must be https (http only on this PC) |
| vuln-0001 | Medium | The dev sign-in guard checked `PUBLIC_URL` but the server listened on every network interface | With `DEV_LOGIN=1` the server binds to 127.0.0.1 and dev routes refuse non-loopback clients; `HOST` sets the address otherwise |
| vuln-0010 | Medium | An upload held open past `/complete` could replace the finished file with a bigger one (local storage) | The upload is moved into place only if its clip is still pending, checked in the same step; each upload writes its own temp file; `/complete` also enforces the minimum size |
| vuln-0012 | Medium | Real ad ids could be clicked or viewed without limit | Each address counts once per card per day for clicks and 6 times per hour for views |
| vuln-0002, 0003, 0004, 0005 | Medium/Low | Electron 37 (unsupported) has four published CVEs, including context-isolation bypasses | Upgraded to Electron 42.11.18. Pages can no longer read `cf://file` with fetch; playback is unaffected |
| vuln-0007, 0008 | Info | `@anthropic-ai/sdk` 0.80 memory-tool flaws | Not used by Clutch (no memory tool). Left for the 1.x SDK upgrade |
| vuln-0009 | Info | zod 3 large-array DoS | zod only shapes model output in the server, never request bodies. Left for later |

Still open from Strix's list: per-IP rate limits on the rest of the API, session revocation, and moving the token out of the sign-in redirect URL.
