## Description

`@anthropic-ai/sdk` 0.79.0 up to 0.91.0 creates files with insecure default permissions in its local filesystem memory tool helper. Fixed in 0.91.1. Both lockfiles pin 0.80.0.

## Evidence

**Advisory evidence:** `CVE-2026-41686` applies to `@anthropic-ai/sdk` at installed version `0.80.0`. The advisory is fixed in `0.91.1`.

**Usage analysis:** imported by application code; affected API usage unconfirmed. Imports at src/main/triggers/titler.ts:1, src/main/triggers/vision.ts:1, src/main/importer/smart.ts:1, server/src/vision.mjs:1, server/src/importer.mjs:1; only `messages.parse` is called (server/src/importer.mjs:54, server/src/vision.mjs:38). No reference to the local filesystem memory tool exists in src/ or server/src/. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

None in the current code, because the memory tool helper is never used; the application only calls `messages.parse`.

## Contextual CVSS

The memory helper that creates files with loose permissions is never called; the five SDK call sites only use `messages.parse` (server/src/importer.mjs:54, server/src/vision.mjs:38), so no file is created and impacts are None. Rating changes if the memory tool is enabled.

## Remediation

Upgrade `@anthropic-ai/sdk` to 0.91.1 or later in both package.json files and regenerate the lockfiles. Test the `messages.parse` and `zodOutputFormat` call sites after the upgrade, as the newer major may change helper APIs.

## Assumptions

Same usage analysis as for CVE-2026-34451: no memory tool symbols are referenced in src/ or server/src/. The same version appears in server/package-lock.json.
