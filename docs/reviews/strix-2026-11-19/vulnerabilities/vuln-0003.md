# CVE-2026-70604 in electron 37.10.3 (custom protocol with supportFetchAPI but without corsEnabled allows cross-origin reads)

**ID:** vuln-0003
**Severity:** LOW
**Found:** 2026-11-19 17:03:50 UTC
**Target:** clutch (root package-lock.json, desktop app runtime)
**Package:** electron
**Ecosystem:** npm
**Installed Version:** 37.10.3
**Fixed Version:** 39.8.10
**CVE:** CVE-2026-70604
**CVSS:** 3.1
**Advisory CVSS:** 7.4
**Contextual CVSS Vector:** CVSS:3.1/AV:N/AC:H/PR:N/UI:R/S:U/C:L/I:N/A:N
**Fix Effort:** Low

## Description

Electron before 39.8.10 lets other origins read responses from a custom scheme that is registered with `supportFetchAPI` but without `corsEnabled`. The application registers exactly such a scheme (`cf`) and the lockfile pins `electron` 37.10.3, which is end-of-life and will not receive the fix.

## Evidence

**Advisory evidence:** `CVE-2026-70604` applies to `electron` at installed version `37.10.3`. The advisory is fixed in `39.8.10`.

**Usage analysis:** the advisory's affected API is used in application code. src/main/index.ts:41 calls `protocol.registerSchemesAsPrivileged([{ scheme: 'cf', privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true, bypassCSP: true } }])` with no `corsEnabled`; the handler is `protocol.handle('cf', ...)` at src/main/index.ts:330 and serves files via `serveFile` (src/main/fileServer.ts:34). Entry: foreign-origin document in a Clutch window -> fetch('cf://file/<path>') -> handler at index.ts:330. Nothing in the app loads foreign-origin documents (navigation blocked at src/main/security.ts:58-65, `will-attach-webview` prevented). This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

The `cf://file/<path>` handler serves local clips, thumbnails and icons from the clips folder, userData and library folders. Content from another origin that is loaded into an Electron window could fetch those files. The app only loads its own `cf://app/` UI and blocks navigation and popups, so no cross-origin content was identified that can run in a Clutch window; the issue is latent.

## Contextual CVSS

The scheme is registered at src/main/index.ts:41 with `supportFetchAPI` and no `corsEnabled`, which matches the advisory precondition. The handler at src/main/index.ts:330-342 only returns files with media extensions from the clips folder, userData and library folders (isServableMedia/isInside in src/main/security.ts:46-50), and no foreign-origin content can execute in a Clutch window (lockWindow, src/main/security.ts:58-65), so complexity is High and impact is limited to clip media (Confidentiality Low). The published 7.4 is lowered for those reasons.

## Remediation

Upgrade `electron` to a supported release containing the fix (39.8.10, 40.9.3, 41.4.0 or 42.0.0 and later). Independently, review whether the `cf` scheme needs `supportFetchAPI`; if the renderer only uses it for media and image elements, drop that privilege.

## Assumptions

Requires non-Clutch content running in an Electron window of the app. Clutch's windows use `lockWindow` to deny navigation and popups and the CSP forbids framing external pages. The renderer CSP also allows `img-src https:` but images cannot read cross-origin responses.
