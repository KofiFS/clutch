# CVE-2026-70610 in electron 37.10.3 (contextBridge object copy honors prototype setters)

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-11-19 17:04:16 UTC
**Target:** clutch (root package-lock.json, desktop app runtime)
**Package:** electron
**Ecosystem:** npm
**Installed Version:** 37.10.3
**Fixed Version:** 39.8.9
**CVE:** CVE-2026-70610
**CVSS:** 4.2
**Advisory CVSS:** 5.4
**Contextual CVSS Vector:** CVSS:3.1/AV:N/AC:H/PR:N/UI:R/S:U/C:L/I:L/A:N
**Fix Effort:** Low

## Description

Electron before 39.8.9 copies objects across the `contextBridge` boundary in a way that honors prototype setters defined by page script. The app exposes a large `cf` API through `contextBridge.exposeInMainWorld` and pins `electron` 37.10.3, which will not receive a fix.

## Evidence

**Advisory evidence:** `CVE-2026-70610` applies to `electron` at installed version `37.10.3`. The advisory is fixed in `39.8.9`.

**Usage analysis:** the advisory's affected API is used in application code. `contextBridge.exposeInMainWorld('cf', api)` at src/preload/index.ts:185; bridge methods forward renderer arguments to `ipcRenderer.invoke(...)` (for example src/preload/index.ts:171-178). Trace: renderer main-world script (separate injection bug required) -> bridge call with crafted object -> preload wrapper -> ipcMain.handle in src/main/index.ts. Input is controlled by script in the renderer. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

A script already running in the renderer main world can run its own code during bridge argument copying, which can make privileged-side bridge code observe attacker-controlled values. Bridge arguments are forwarded to `ipcRenderer.invoke` and validated in the main process, so impact is limited to the existing IPC trust level; no renderer script-injection primitive was confirmed.

## Contextual CVSS

The bridge is created at src/preload/index.ts:185 and every argument ends in ipcMain handlers that re-validate inputs (for example `clipPatchFromRenderer` in src/main/security.ts:31-39). Exploitation needs prior renderer script execution under the CSP at src/renderer/index.html:6, so complexity is High and user interaction Required, and the effect stays inside what the renderer can already call over IPC.

## Remediation

Upgrade `electron` to 39.8.9 or later (40.9.2, 41.2.2, 42.0.0-beta.4 or later on newer lines). Keep validating every IPC argument in the main process.

## Assumptions

Requires script execution in the renderer main world from a separate bug. Fix is only published for supported majors; Electron 37 is end-of-life.
