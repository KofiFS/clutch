# CVE-2026-70601 in electron 37.10.3 (context isolation bypass via Function.prototype.bind hijack)

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-11-19 17:03:36 UTC
**Target:** clutch (root package-lock.json, desktop app runtime)
**Package:** electron
**Ecosystem:** npm
**Installed Version:** 37.10.3
**Fixed Version:** 39.8.9
**CVE:** CVE-2026-70601
**CVSS:** 4.7
**Advisory CVSS:** 7.5
**Contextual CVSS Vector:** CVSS:3.1/AV:N/AC:H/PR:N/UI:R/S:C/C:L/I:L/A:N
**Fix Effort:** Low

## Description

Electron before 39.8.9 (and the 40.x/41.x/42.x lines before their patched releases) allows script running in a page's main world to bypass context isolation by hijacking `Function.prototype.bind`. The lockfile pins `electron` 37.10.3, an unsupported release line that will not receive this fix, and `electron-builder` packages this exact binary as the shipped runtime even though it is listed under `devDependencies`.

## Evidence

**Advisory evidence:** `CVE-2026-70601` applies to `electron` at installed version `37.10.3`. The advisory is fixed in `39.8.9`.

**Usage analysis:** the advisory's affected API is used in application code. The preload script calls `contextBridge.exposeInMainWorld('cf', api)` (src/preload/index.ts:185) and the main window is created with `contextIsolation: true, sandbox: true` (src/main/index.ts:81), so context isolation is the active boundary this CVE defeats. Trace: renderer main-world script (needs a separate XSS/injection primitive, none confirmed) -> bind hijack -> access to the bridge objects in src/preload/index.ts -> ipcRenderer.invoke handlers in src/main/index.ts. Input is controlled by whoever can run script in the renderer; nothing in the repo reaches it today without another bug. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

If an attacker obtains script execution in the renderer main world (for example through an XSS bug in the renderer), the context-isolation boundary that separates the `cf` preload API from page script can be bypassed. The renderer's trust boundary toward the privileged preload and IPC surface then depends on the main-process input validation alone. No renderer script-injection primitive was confirmed by this analysis.

## Technical Analysis

Electron's context-isolation implementation relies on JavaScript built-ins from the isolated world. In affected versions, a main-world script that replaces `Function.prototype.bind` can obtain references that cross the isolation boundary. Trivy does not cover this advisory; it was found with `npm audit --package-lock-only` against the lockfile. The same lockfile entry is affected by several other Electron advisories listed by `npm audit` (for example CVE-2026-70610, CVE-2026-70604 and CVE-2026-34767).

## Contextual CVSS

The vulnerable boundary is `contextIsolation: true` in src/main/index.ts:81 with the preload bridge at src/preload/index.ts:185. The renderer only loads `cf://app/index.html` under a strict CSP (src/renderer/index.html:6) and navigation is locked by `lockWindow` (src/main/security.ts:58-65), so an attacker first needs a separate script-injection bug and a user opening crafted content; complexity is therefore High and user interaction Required. The published rating of 7.5 is lowered because every IPC handler additionally validates its inputs in the main process, so the bypass alone yields limited confidentiality and integrity impact.

## Remediation

Upgrade `electron` to a supported release that contains the fix (39.8.9 or later on the 39 line, or 40.9.2, 41.2.2 or 42.0.0-beta.5 and later). Electron 37 is end-of-life and also lacks fixes for the other advisories reported by `npm audit`. Re-run the end-to-end tests after the upgrade because the main process relies on `protocol.handle`, `registerSchemesAsPrivileged` and `getDisplayMedia` behaviour.

## Assumptions

Exploitation needs an independent primitive that runs JavaScript in the renderer main world. The renderer CSP (`script-src 'self' blob:`) and `will-navigate`/`setWindowOpenHandler` locks reduce that likelihood. The advisory's affected range is `< 39.8.9` per the GitHub advisory, which formally includes 37.x although 37.x is no longer maintained.
