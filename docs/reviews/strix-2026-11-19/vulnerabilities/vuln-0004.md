# CVE-2026-34768 in electron 37.10.3 (unquoted executable path in app.setLoginItemSettings on Windows)

**ID:** vuln-0004
**Severity:** LOW
**Found:** 2026-11-19 17:04:04 UTC
**Target:** clutch (root package-lock.json, desktop app runtime)
**Package:** electron
**Ecosystem:** npm
**Installed Version:** 37.10.3
**Fixed Version:** 38.8.6
**CVE:** CVE-2026-34768
**CVSS:** 3.3
**Advisory CVSS:** 3.9
**Contextual CVSS Vector:** CVSS:3.1/AV:L/AC:H/PR:L/UI:R/S:U/C:L/I:L/A:N
**Fix Effort:** Low

## Description

Before 38.8.6, Electron's `app.setLoginItemSettings` on Windows writes the executable path to the Run registry key without quotes. When the install path contains a space, Windows can resolve a shorter path prefix to an attacker-placed executable at login. Clutch calls this API when the user enables "launch at login" and pins `electron` 37.10.3.

## Evidence

**Advisory evidence:** `CVE-2026-34768` applies to `electron` at installed version `37.10.3`. The advisory is fixed in `38.8.6`.

**Usage analysis:** the advisory's affected API is used in application code. `applyLaunchAtLogin` calls `app.setLoginItemSettings({ ...loginItem(), openAtLogin: on })` at src/main/index.ts:169; for the packaged app `loginItem()` returns `{ args: ['--hidden'], name: 'Clutch' }` (src/main/index.ts:156-160) so Electron derives the unquoted path itself. Entry: user toggles launch-at-login in the settings UI -> settings handler -> applyLaunchAtLogin -> app.setLoginItemSettings. The user controls the trigger; the attacker needs separate local file-write access on an ancestor directory. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

A local, low-privilege attacker who can write an executable into a parent directory of the install path could obtain code execution as the user at next login. The default per-user install location is under %LOCALAPPDATA%\Programs, so a prefix write is only possible when the Windows user-profile path contains a space and the user can create files at a directory such as C:\Users, which standard users normally cannot do.

## Contextual CVSS

`applyLaunchAtLogin` (src/main/index.ts:167-170) calls setLoginItemSettings on Windows for the packaged app with no explicit `path` (src/main/index.ts:156-160), which is the affected pattern. Exploitation needs local file-write access in an ancestor directory of the install path and a path containing a space, so the vector stays Local with High complexity and the impact matches the published low rating.

## Remediation

Upgrade `electron` to 38.8.6 or later (39.8.1 or later on the 39 line, or a newer supported major). Until then, set the login item `path` explicitly to a quoted executable string.

## Assumptions

Windows only; requires launch-at-login to be enabled and an install path containing a space, plus write access to an ancestor directory. Installer allows a custom install directory (package.json build.nsis.allowToChangeInstallationDirectory), which could make a writable prefix more likely.
